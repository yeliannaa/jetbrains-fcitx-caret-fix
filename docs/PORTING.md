# 适配其他 IDE / JBR 的工作记录模板

此文档用于指导开发者或 AI 调查，例如 PyCharm 2022 + JBR 17。它不表示该组合已可安装，也不保证适配只需改几个参数。

## 先建立独立测试条件

复制目标 IDE 到可丢弃目录，使用临时配置目录和测试文件，保留正常使用的 IDE。记录 IDE 完整构建号、实际 Java 运行时版本、`libawt_xawt.so` 哈希、输入框架/插件版本、X11/Wayland、屏幕与 DPI、缩放及字体。先复现未打补丁的行为。

安装器只改启动脚本不等于没有运行时影响：启动器会选择 JBR、设置输入法环境及 UI 缩放。每个变量应单独核对，字体回归必须列入验收。

## 定位坐标在哪里丢失

1. 检查输入组件的 `InputMethodRequests.getTextLocation(TextHitInfo.leading(0))`。记录坐标和矩形高度，不记录文本内容。
2. 检查实际输入实现是否仍为 X11 XIM；若是 Wayland 原生实现，不能套用此 JNI 链路。
3. 比较 AWT 屏幕坐标、X11 root 坐标、焦点窗口相对坐标，单屏、多屏分别移动编辑光标验证。
4. 验证候选位置原本应由哪一层更新，优先复用目标 JBR 已提供的公开或内部位置更新方法；能避免裸指针访问时应重新评估实现。

## 必须重新确认的 JBR 私有接口

| 当前假设 | 目标版本需确认 |
| --- | --- |
| `sun.awt.im.InputContext.inputMethod` | 字段所在类、类型、可反射性 |
| `sun.awt.X11InputMethodBase.pData:J` | 字段是否仍存在及 native 对象生命周期 |
| `sun.awt.X11.XInputMethod.getXICFocus():J` | 方法签名、线程/锁约束 |
| native `X11InputMethodData` 首字段为 `current_ic` | 与目标二进制对应的源码、结构布局和 ABI |
| `SunToolkit.awtLock/awtUnlock` | 所需同步方式和调用线程 |
| Java 11 module opens/exports | 目标 Java 模块封装、启动时异常 |

以**目标二进制对应的提交**为依据，不以最新分支源码替代。当前参考提交是 `7bea9b450563`；哈希仅是拒绝未知 ABI 的门槛，不能证明另一个哈希的结构相同。错误 native 指针可能直接导致 JVM 崩溃。

如适配 JBR 17，应重新检查上述全部接口、构建 agent/bridge、调整 `premain` 的 Java 版本与哈希验证，并为安装器增加独立且经过测试的兼容配置。不要仅把 `"11"` 改为 `"17"` 或把一个哈希替换成另一值后发布。

## 为什么现在是 -50 像素

在本次调查的 Fcitx 4 XIM 链路里，传给前端的窗口高度可能为 0；特定搜狗 4.2.1 插件把此值替换为 `0x32`（50），导致可见候选窗口相对发送位置再下移约 50 像素。原环境实际测量与此一致，所以启动器传 `-Dlocal.ime.yOffset=-50`，Java 代码默认值仍为 0。

新插件、输入框架、缩放环境必须重新测量；禁止把 -50 当成所有版本都通用的修复。位置测量要区分窗口边界、皮肤透明留白和文字基线。

## 验收与回滚

- 普通拼音、数字/英文、搜狗特殊输入模式；编辑区、搜索框、弹窗及不同组件。
- 光标移动、文本滚动、窗口移动/缩放、多屏、焦点切换和屏幕边缘。
- 无候选窗口、退出/重开、输入法切换；透明皮肤是否出现黑底、是否有焦点抢占。
- 候选内容不变、组合输入不丢失、字体/字号不意外变化；性能与异常日志。
- 安装、重复安装、拒绝不匹配版本、卸载原样恢复；多实例与已修改启动器。

先通过独立测试副本，再由使用者验证正式环境。为新组合补充兼容表、构建哈希、证据和回滚步骤；自动安装测试不能代替桌面验收。
