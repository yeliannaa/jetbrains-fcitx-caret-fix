# 测试方式

## 自动测试

```bash
bash build.sh
python3 -B -m unittest discover -s tests -v
bash package.sh
```

安装器测试只使用 Python 标准库，每个用例在临时目录构造 IDE、启动脚本、Java 命令和插件。测试进程自己的 PATH 提供 `uname`、`fcitx`、`ldd`、`sha256sum` 模拟器；只有两个确定的假文件内容返回兼容哈希，包清单和备份校验仍调用真实 sha256sum。生产脚本不存在测试模式、跳过校验或任意哈希开关。

覆盖：只读检查、首次安装、参数与特殊路径、重复安装、目录迁移、备份和启动器被修改时拒绝、依赖/构建/插件/会话不匹配、锁冲突、旧环境失效后的卸载、字节级与权限恢复、ZIP 往返和固定输入重复打包。

另外 4 项启动回归测试使用现有 JDK 编译并运行独立的无界面 JVM，验证补丁等待 IDE 事件线程、保留其类加载器并正确计算复选框宽度，以及既有线程、超时和错误类加载器的处理。共 29 项自动测试。

测试无需搜狗、运行中的桌面或真正的 PyCharm，不会执行 JNI。GitHub CI 运行同一套测试，**不能证明光标跟随、透明度、输入法行为或 native ABI 在新环境中正确**。

## 桌面验证

仅在明确确认的测试副本运行，记录测试版本和库哈希。

1. 记录未修补状态的候选位置、字体、字号和缩放。
2. `install.sh --check` 后安装，完全退出并从修补入口重启 IDE。
3. 确认实际 JBR 和 `[caret-bridge] active`；检查普通拼音、特殊输入、搜索/弹窗。
4. 移动光标、滚动、移动窗口、跨屏、边缘输入、切换焦点，核对文字、候选框、透明度和字体。
5. 检查提交列表复选框的鼠标和空格勾选，完整重启后复查；检查日志中是否出现 `no ComponentUI class`。
6. 卸载后比较原启动脚本字节及权限，重启确认恢复。

不要在自动 CI 中用模拟成功宣称新 JBR 兼容。完整适配清单见 [PORTING.md](PORTING.md)。
